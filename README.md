# kmradar — радар поводов для КМ

MVP «снаружи банка»: КМ задаёт регион, отрасли (ОКВЭД), диапазон выручки и
продукты. Каждое утро получает до 7 карточек о событиях у компаний этого
профиля — только из открытых источников. Клиент это или нет, КМ проверяет сам
в банковских системах. Банковские данные в систему не попадают.

Полное описание продукта: [docs/mvp.md](docs/mvp.md). Источники данных — [docs/data-sources.md](docs/data-sources.md).

## Быстрый старт

Python 3.10+, сторонних зависимостей нет (pytest — только для тестов).

```bash
python -m kmradar demo        # 4 дня на вымышленных компаниях Тверской области
python -m pytest -q           # тесты
```

Боевой цикл:

```bash
python -m kmradar add-km kms.json                         # профили КМ
python -m kmradar run --source data/ --out out/            # ночной прогон за сегодня
python -m kmradar run --source data/ --telegram            # то же, доставка в Telegram (TELEGRAM_TOKEN)
python -m kmradar bot                                      # приём нажатий кнопок
python -m kmradar feedback 12 contacted                    # ответ вручную (useful|miss|knew|contacted)
python -m kmradar outcome 12 meeting                       # итог (meeting|application|refusal|nothing)
python -m kmradar metrics                                  # метрики пилота с порогами
```

`run` по cron в ~03:00, дайджест уходит сразу после прогона; рассылка к 08:30 —
отдельной задачей по cron, если нужен точный час.

## Статичный пример

`https://ваш-домен/demo` — интерактивный пример без базы и настроек: дайджест КМ
на выдуманных компаниях, кнопки, разбор скоринга и метрики пилота. Нажатия
сохраняются только в браузере смотрящего.

## Запуск на сервере

Каждый КМ получает личную ссылку и открывает дайджест в браузере — с
компьютера или телефона. Telegram не нужен (можно включить как дубль).

**Что нужно:** VPS в России (персональные данные граждан РФ хранятся в РФ),
Ubuntu 22.04+ или Debian 12+, 1 ядро и 1 ГБ памяти; домен, A-запись которого
указывает на IP сервера; открытые порты 80 и 443.

```bash
git clone https://github.com/ker4anin-arch/kmradar.git && cd kmradar
sudo ./deploy/install.sh          # создаст /etc/kmradar.env и остановится
sudo nano /etc/kmradar.env        # BASE_URL=https://ваш-домен
sudo ./deploy/install.sh          # включит сайт, HTTPS (Caddy) и утренний запуск
```

Профили КМ — JSON как `fixtures/demo/kms.json` (`chat_id` для веба не нужен),
затем личные ссылки:

```bash
cd /opt/kmradar
sudo -u kmradar python3 -m kmradar add-km --db /var/lib/kmradar/radar.db /path/kms.json
sudo -u kmradar python3 -m kmradar link --db /var/lib/kmradar/radar.db --base-url https://ваш-домен all
```

Ссылку отправьте КМ лично: по ней открывается его дайджест, пароля нет.
Новая ссылка (`link <km_id>`) отключает старую. В базе хранится только хеш
ссылки, в журнал сервера она не пишется.

**Если на сервере уже есть сайты.** Скрипт не меняет основной
`/etc/caddy/Caddyfile` и nginx. Если Caddyfile подключает
`import /etc/caddy/sites/*.caddy`, радар кладёт туда только свой файл
`kmradar.caddy` и перезагружает Caddy лишь после успешной проверки всего
конфига. Иначе скрипт печатает блок для ручного добавления. Порт радара
выбирается свободный (от 8091) и сохраняется в `/etc/kmradar.env` (`RADAR_PORT`).

Что работает после установки:

- `kmradar-web` — сайт на 127.0.0.1:`RADAR_PORT`, снаружи — через Caddy по HTTPS;
- `kmradar-daily.timer` — по будням в 08:25 по Москве собирает события из
  `/var/lib/kmradar/data/<дата>.json` и готовит дайджесты;
- на странице: карточки с кнопками, «Чем закончилось?» через 7 дней после
  «Связался», вопрос о причине после трёх «мимо» подряд.

Пока нет подключений к Checko и ЕИС, файл дня кладёт аналитик (режим Wizard of
Oz, формат ниже). Обновление кода: `git pull && sudo ./deploy/install.sh`.
Проверка: `systemctl status kmradar-web`, `journalctl -u kmradar-daily`,
метрики — `sudo -u kmradar python3 -m kmradar metrics --db /var/lib/kmradar/radar.db`.

Telegram как дубль: `TELEGRAM_TOKEN` в `/etc/kmradar.env` (при блокировках —
`HTTPS_PROXY`), `chat_id` в профилях КМ и `--telegram` в `kmradar-daily.service`.

## Данные из Checko

Ключ — `CHECKO_API_KEY` в `/etc/kmradar.env`. Территория — файл
`/var/lib/kmradar/territory.txt`, по ИНН в строке (`#` — комментарий). Если файл
есть, ночной прогон берёт данные из Checko; файлы аналитика в
`/var/lib/kmradar/data` по-прежнему подхватываются.

| Что | Запрос Checko | Как часто |
| --- | --- | --- |
| Директор, учредители, капитал, ОКВЭД, филиалы, МСП, статус | `company` | каждый день |
| Лизинг, залоги, намерения о банкротстве, ликвидация | `fedresurs` | каждый день |
| Заключённые госконтракты 44-ФЗ и 223-ФЗ | `contracts` | каждый день |
| Долги ФССП, сообщения ЕФРСБ | `enforcements`, `bankruptcy-messages` | раз в неделю |
| Выручка и дебиторка | `finances` | раз в месяц |

Это расписание платного тарифа (`CHECKO_PLAN=paid`): в среднем 4,3 запроса на
компанию в день, 100 компаний — около 430 запросов.

**Бесплатный ключ** (`CHECKO_PLAN=free`, по умолчанию; 100 запросов в день):
Федресурс — каждый день, карточка компании — раз в 3 дня, контракты 44-ФЗ и
223-ФЗ — раз в неделю, долги и ЕФРСБ — раз в месяц, отчётность — раз в 3 месяца. Около 1,7
запроса на компанию, держится ~55 компаний. Радар читает из ответов Checko,
сколько запросов потрачено за сутки, и останавливается за 3 до лимита — дальше
данные из кеша. Данные, пришедшие впервые позже остальных (например,
отчётность), не дают ложных событий «рост выручки» или «новые долги».

Быстро набрать территорию, где события есть в первый же день:
`python3 -m kmradar checko-seed --limit 10 territory.txt` — компании со свежими
договорами лизинга (1 + 10 запросов). При первом снимке радар сразу поднимает
датированные события последних недель: новый директор или учредитель, лизинг,
залоги, банкротство.
Посчитать для своей территории: `python3 -m kmradar checko-plan territory.txt`.
Проверить разбор одной компании: `python3 -m kmradar checko-test --db ... <ИНН>`.

Ответы кешируются в `/var/lib/kmradar/checko-cache`. При сбое запроса берётся
последний удачный ответ; компания без единого ответа в этот день пропускается,
чтобы неполные данные не дали ложных событий.

Важно про госконтракты: Checko показывает уже **заключённые** контракты —
гарантия исполнения к этому моменту внесена. Поэтому это отдельный сигнал
«Заключён госконтракт» (оборотка, гарантия на аванс), а не срочная «Победа в
закупке». Для срочного повода нужны протоколы итогов ЕИС.

## Ручные поводы (Wizard of Oz)

Аналитик вносит найденные поводы формой по админ-ссылке:
`python3 -m kmradar admin-link --db ... --base-url https://ваш-домен`.

Форма: ИНН, тип повода (победа в закупке, госконтракт, смена руководителя,
лизинг, новость, стоп-сигнал), дата, факты и **обязательная ссылка на
источник**. Название, регион и ОКВЭД радар берёт из Checko (1 запрос), а без
Checko их можно вписать руками. Карточка сразу уходит КМ, под чей профиль
подходит компания, или КМ, отмеченным галочкой. Правило «слабый день два раза
подряд» к ручным поводам не применяется.

## Мои компании

На странице КМ есть раздел «Мои компании»: КМ сам добавляет до 20 ИНН холодных
компаний (**только не клиентов банка** — ввод ИНН клиента раскрыл бы факт
обслуживания; предупреждение стоит прямо над полем). ИНН проверяется по
контрольной цифре.

После добавления радар сразу в фоне берёт данные из Checko (нужен
`CHECKO_API_KEY` в `/etc/kmradar.env`) и показывает по каждой компании события
за полгода: директор, учредители, госконтракты, отчётность, банкротства. Свежие
события дальше приходят в утренний дайджест этого КМ, даже если компания не
подходит под его профиль. Другие КМ чужие списки не видят.

## Новости

Файл `/var/lib/kmradar/feeds.txt` — источники по одному в строке. Установка кладёт
туда стартовый список из `deploy/feeds.txt` (22 проверенных источника: федеральные
деловые СМИ и региональные Telegram-каналы), если файла ещё нет; дальше его
правите сами. Формат: RSS/Atom-фид,
`https://t.me/<канал>` или `@канал` (публичные Telegram-каналы). Разбор фидов
перенесён из uuagent2 и работает без сторонних библиотек.

Новость становится событием «Компания в новостях», только если в ней есть
компания из базы радара: по ИНН, по названию в кавычках («Теплострой») или по
названию из двух и более слов целиком. Названия короче 5 букв — только по ИНН.
Проверить источники: `python3 -m kmradar news-test --db ... /var/lib/kmradar/feeds.txt`.

## Как устроено

```
источник → снимок → разница со вчера → события → скоринг → лимиты → карточка → КМ
                                                     ↑                          │
                                                     └──── обратная связь ──────┘
```

| Модуль | Что делает |
| --- | --- |
| `sources.py` | Протокол источника, `FixtureSource` (JSON по дням), `CompositeSource` |
| `news.py` | Новости из RSS и Telegram-каналов, поиск компаний в тексте |
| `checko.py` | Данные из Checko: снимки компаний, Федресурс, контракты, кеш |
| `diff.py` | Снимок сегодня − снимок вчера = события 2–8; протоколы ЕИС → событие 1 |
| `scoring.py` | `score = W × F × S × P × личный вес КМ` |
| `digest.py` | Склейка событий компании, стоп-сигналы, неделя тишины, лимиты 7 + 3 срочных, пропуск слабых дней |
| `cards.py` | Карточка: факты — шаблоном из данных, пустых полей нет |
| `writer.py` | «Зачем звонить / Первая фраза / Спросить»: шаблоны или LLM с проверкой |
| `feedback.py` | Кнопки, личные веса, вопрос после 3 «мимо», вопрос об итоге через 7 дней |
| `metrics.py` | Метрики пилота и пороги «идём дальше / стоп» |
| `web.py` | Веб-дайджест по личной ссылке КМ: карточки, кнопки, итоги, «Мои компании» |
| `admin.py` | Форма аналитика «Добавить повод» |
| `watch.py` | «Мои компании»: проверка ИНН, загрузка с историей за полгода |
| `delivery.py`, `bot.py` | Консоль, файлы Markdown, Telegram |
| `storage.py` | SQLite; схема переносится в Postgres |

Все веса, окна и лимиты — в `config.py`.

### Правила, которые зашиты в код

- **LLM не пишет фактов.** Цифры, даты, номера, суммы подставляются шаблоном.
  Ответ LLM отклоняется и заменяется шаблоном, если в нём есть цифры, гипотеза
  не помечена как гипотеза («скорее всего», «может») или в первом предложении
  фразы назван продукт.
- **Стоп-сигнал** (ликвидация, банкротство, крупные долги ФССП) подавляет
  карточки по компании на 90 дней и приходит строкой «⚠️ Осторожно».
- **Одна компания — одна карточка в неделю;** все свежие события компании
  склеиваются в одну карточку, срочное идёт первым. Событие, уже показанное КМ, повторно не приходит.
- **Нажимать кнопки карточки может только КМ, которому она отправлена.**

### Решения там, где документ допускает толкования

- `S` для закупок: сумма к медиане территории, потолок 2,0 **и пол 0,5** —
  иначе контракт сильно ниже медианы обнулял бы самый сильный тип сигнала.
- Пропуск дайджеста (меньше 3 сильных карточек два дня подряд) **не трогает
  срочные**: победа в закупке с окном в несколько дней уходит всё равно.
  Первый день, за который нет вчерашних данных, не считается слабым.
- «Уже знал» и «мимо» считаются от карточек с ответом, «связался» — от всех.
- Открытие дайджеста = КМ открыл страницу этого дня или нажал кнопку
  (Telegram о прочтении не сообщает, поэтому там считаются только нажатия).
- Окно сигнала МСП — 60 дней, отчётности — 90 (в документе «раз в год»).

## Формат данных источника

Каталог с файлами `YYYY-MM-DD.json`:

```json
{
  "snapshots": [ { "inn": "...", "name": "...", "region": "69", "okved_main": "42.11", "...": "..." } ],
  "tenders":   [ { "inn": "...", "date": "2026-10-14", "amount": 186000000, "subject": "...",
                   "customer": "...", "number": "...", "law": "44", "url": "..." } ],
  "events":    [ { "inn": "...", "type": "tender_win", "date": "2026-10-14", "facts": {}, "url": "..." } ]
}
```

Полный формат снимка — в docstring `kmradar/diff.py`, пример — `fixtures/demo/days/`.

`events` — для фазы Wizard of Oz: аналитик кладёт найденные руками события,
радар делает из них карточки по тем же правилам и считает метрики. Компания
события должна быть в `snapshots` того же или более раннего дня.
